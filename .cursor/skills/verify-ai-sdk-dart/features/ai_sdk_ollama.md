# ai_sdk_ollama

The Ollama provider. `OllamaProvider` (and the default `ollama` instance) gives a developer a language model and an embedding model for a local Ollama server. It needs no API key. Chat uses `/api/chat` with NDJSON streaming. Embeddings use `/api/embed`.

## Sub-features

- `ollama-generate` sends `POST <baseUrl>/chat` with `model`, `messages`, `stream: false` and an `options` object (`num_predict`, `temperature`, `top_p`, `top_k`, `seed`, `stop`), sends no `Authorization` header, and returns text, usage (`prompt_eval_count`, `eval_count`) and the finish reason (`done_reason`).
- `ollama-stream` sends `stream: true`, reads the NDJSON lines into ordered text deltas, and reports usage and the finish reason from the `done: true` line.
- `ollama-tools` serializes tools as `function` tools, parses whole `tool_calls` (arguments are a JSON object) in plain and streamed replies, sends the assistant `tool_calls` and a `tool` message with `tool_name` back, and sets the finish reason to `toolCalls`.
- `ollama-multimodal` sends an image part as a raw base64 string in the message `images` array.
- `ollama-embed` sends `POST <baseUrl>/embed` with `model` and `input` (plus `providerOptions['ollama']`), and returns the vectors in input order.
- `ollama-options` merges `providerOptions['ollama']` (for example `num_ctx`, `repeat_penalty`) into `options`, and passes per-call `headers` to the server.
- `ollama-provider` covers the provider options: `baseUrl`, the default `http://localhost:11434/api`, an injected `client`, `dispose()`, and the absence of any auth header.
- `ollama-errors` maps a non-2xx `{error: "..."}` body to `AiApiCallError` for chat, streamed chat and embed, and reports an `{error}` line after streaming started and a stream that ends without `done: true` as typed errors.

## How to get to it (user POV)

- Call `ollama('llama3.2')` or `OllamaProvider(baseUrl: ...)('...')` and pass the model to `generateText` or `streamText` from `ai_sdk_dart`.
- Call `ollama.embedding('nomic-embed-text')` and pass it to `embed` or `embedMany`.

## Gotchas

- The fixture responses follow the public Ollama API format. They prove the adapter's mapping, not a real model's behavior.
- The default base URL is `http://localhost:11434/api` and the package never sends an `Authorization` header. A proxy that needs a key must get it through the per-call `headers` argument.
- Tool calls arrive whole, not as deltas. The tool call id is generated by the package (`ollama-tool-...`) because Ollama sends none.
- Not covered: structured output (`Output.object`): the adapter does not send Ollama's `format` field.
- Not covered: thinking or reasoning output: the adapter has no mapping for `think` or `message.thinking`.
- Not covered: remote image URLs: the adapter only sends inline image bytes.
- When the caller sets no `system`, the adapter still sends `{"role": "system", "content": ""}` as the first message. The checks do not assert on this.
- `generateText` retries retryable errors. `maxRetries: 0` prevents retries, but a retryable error is still wrapped in `AiRetryError`. Read `lastError` for its `AiApiCallError`.
