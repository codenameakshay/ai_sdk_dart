# CONTEXT

Domain vocabulary and architecture map for **AI SDK Dart** — a Dart/Flutter SDK aligned with
Vercel AI SDK's V4 provider seam. Use these terms consistently in code, docs, and architecture
reviews.

## What this is

A provider-agnostic SDK: write AI logic once, swap providers without touching business code. Core
functions run in any Dart runtime (mobile, web, desktop, server). Calling providers directly from
a Dart process suits local development and trusted Dart servers. Production Flutter apps should
send conversations to a trusted backend through `ai_sdk_remote`, so provider credentials,
authorization, and tool execution stay on the server. See `README.md` and
`docs/adr/0006-remote-conversation-transport.md`.

## Domain vocabulary

- **Provider** — a vendor integration package (`ai_sdk_openai`, `ai_sdk_anthropic`, …). Exposes a
  callable factory (e.g. `openai('gpt-4.1-mini')`) returning a **model**.
- **Model interface** — the contract a provider implements, defined in `ai_sdk_provider`:
  `LanguageModelV4`, `EmbeddingModelV2`, `ImageModelV3`, `SpeechModelV1`, `TranscriptionModelV1`,
  `RerankModelV1`. Each declares a `specificationVersion` and one entry point per capability:
  `doGenerate` / `doStream` (language), `doEmbed`, `doGenerate` (image, speech, transcription),
  `doRerank`. The suffix names a semantic contract, not the package version.
- **Call options** — `LanguageModelV4CallOptions`: the normalized request (prompt, unified tools,
  tool choice, response format, reasoning, `abortSignal`, sampling parameters, headers, and
  provider options) handed to a model.
- **Content part** — a typed piece of a message: text, image, file, reasoning, reasoning file,
  source, tool call, tool result, tool-approval request/response, and opaque provider data.
  Defined once as the sealed `LanguageModelV4ContentPart`; user-facing `ModelMessage.parts` carries
  the same types.
- **Core function** — a top-level entry point in `ai_sdk_dart`: `generateText`, `streamText`,
  `generateObject`, `streamObject`, `embed`, `embedMany`, `generateImage`, `generateSpeech`,
  `transcribe`, `rerank`.
- **Instructions** — the canonical top-level instruction (`instructions:`) on `generateText`,
  `streamText`, `generateObject`, `streamObject`, and `ToolLoopAgent`. It persists across steps
  until `prepareStep` overrides it. `system:` is the legacy fallback; `instructions` wins when both
  are set. System-role input messages are rejected unless `allowSystemInMessages: true`.
- **Tool** — a typed callable the model can invoke: `tool<INPUT, OUTPUT>()`, `toolWithContext()`
  (binds typed application context without sending it to the provider), or `dynamicTool()`.
  A `ToolSet` is `Map<String, Tool<dynamic, dynamic>>`.
- **Approval policy** — `ToolApprovalPolicy` (`never`, `conditional`, `always`); `conditional`
  evaluates the tool's `needsApproval` for each call. Set it at the request or agent boundary with
  `approvalPolicy:`, or per tool with an `approvalPolicyFor:` selector; a tool's own policy is
  only the fallback. A restored approval is bound to the exact call ID, tool name, arguments, and
  policy revision.
- **Tool loop** — the multi-step agentic loop: call model → execute tool calls → feed results
  back → repeat until a **stop condition** trips or no tools are called. Embodied by
  `ToolLoopAgent` (`generate`, `stream`, and `resume` after a paused approval) and inlined in
  `generateText`/`streamText`.
- **Stop condition** — a predicate over a `StepSnapshot` (`stepCountIs`, `hasToolCall`,
  `hasFinishReason`, `never`, `stopWhenAny/All`). `stopWhen` governs the loop; when set it
  overrides `maxSteps`.
- **Step result** — `usage`, `content`, tool calls, sources, and files aggregate every step;
  `text`, structured `output`, and `finalStep` describe the last step. `responseMessages` holds
  only the messages generated by this call, to append once to the caller's history.
- **Output** — structured-output spec (`Output.text/object/array/choice/json`) parsed from model
  text, with `partialOutputStream` / `elementStream` for streaming. `Schema.decoderOnly` trusts the
  decoder; `validatedJsonSchema` (`ai_sdk_json_schema`) validates against a JSON Schema first.
- **Middleware** — a `LanguageModelMiddleware` (or embedding/image) wrapping a model via
  `wrapLanguageModel`: `extractReasoningMiddleware`, `extractJsonMiddleware`,
  `simulateStreamingMiddleware`, `defaultSettingsMiddleware`, `addToolInputExamplesMiddleware`.
- **Stream event taxonomy** — typed `StreamTextEvent` values emitted by `StreamTextResult.stream`
  (start, step boundaries, text/reasoning lifecycles, sources, files, tool input and results/errors,
  raw chunks, usage, and finish events). `fullStream` is a deprecated alias for the same stream;
  `providerStream` exposes the raw `LanguageModelV4StreamPart` values.
- **Cancellation and deadlines** — a `CancellationToken` passed as `abortSignal:` cancels the
  operation and reaches the provider transport and running tools. `TimeoutConfiguration`
  (`total`, `step`, `firstChunk`, `chunk`, `tool`, per-tool `tools`) is the `timeout:` on
  `generateText`, `streamText`, and `ToolLoopAgent`; the other core functions take a `Duration`.
  The earliest active deadline wins.
- **Body inclusion** — `BodyInclusionPolicy` (`bodyInclusion:`) decides whether request bodies,
  response bodies, and raw provider chunks are retained on results. All are omitted by default.
- **Registry** — `createProviderRegistry` / `customProvider`: resolve a model by
  `'provider:modelId'` across categories.
- **Conversation** — `Conversation` (`ai_sdk_conversation`): an immutable, versioned snapshot of
  messages and parts with stable IDs, covering interrupted turns and pending approvals.
  `ConversationCodec` encodes and decodes the persistence schema (version 1); decoding never
  executes tools or fetches files, and unknown parts round-trip unchanged.
- **Remote transport** — `RemoteConversationTransport` (`ai_sdk_remote`): POSTs a `Conversation`
  to a trusted backend and reduces its Vercel UI-message stream (SSE, header
  `x-vercel-ai-ui-message-stream: v1`) into `Conversation` snapshots. Auth comes from an `authHeaders` callback. It never
  executes tools, retries, or resumes a disconnected turn.
- **Controller** — Flutter state adapters in `ai_sdk_flutter_ui`. `ChatController`,
  `CompletionController`, and `ObjectStreamController` are `ChangeNotifier`s over a core
  function or agent. `ConversationController` exposes `Conversation` snapshots from a
  `ConversationBackend`: `LocalConversationBackend` (a `ToolLoopAgent` in process) or
  `RemoteConversationBackend` (a `RemoteConversationTransport`). `ConversationChatController`
  adapts it to the `ChatController` widgets.
- **Telemetry** — `TelemetrySettings` and `TelemetryMetricSink` in core; `ai_sdk_telemetry` adds
  `OtlpHttpMetricSink`, a native-only OTLP/HTTP metrics exporter.
- **Realtime** — `RealtimeSession` over a `RealtimeTransport` (`ai_sdk_realtime`, an unpublished
  preview).
- **MCP** — Model Context Protocol client (`ai_sdk_mcp`): discovers remote tools and exposes them
  as a `ToolSet`.

## Architecture map

```
ai_sdk_provider — the seam: model interfaces, content/stream parts, abort signal
  ▲
  ├── ai_sdk_openai_compatible ◄── openai, groq, mistral, azure
  ├── anthropic, google, cohere, ollama
  ├── ai_sdk_realtime (unpublished preview)
  └── ai_sdk_dart — core: core functions, tool loop, Output, middleware, registry, agent
        ▲
        └── ai_sdk_json_schema, ai_sdk_mcp, ai_sdk_telemetry, ai_sdk_flutter_ui

ai_sdk_conversation ◄── ai_sdk_remote ◄── ai_sdk_flutter_ui
```

| Package | Depends on (`ai_sdk_*`) | Role |
|---|---|---|
| `ai_sdk_provider` | — | The seam: model interfaces, parts, abort signal |
| `ai_sdk_dart` | provider | Core engine |
| `ai_sdk_openai_compatible` | provider | Shared OpenAI Chat Completions base (ADR 0004) |
| `ai_sdk_openai`, `ai_sdk_groq`, `ai_sdk_mistral` | provider, openai_compatible | Providers |
| `ai_sdk_azure` | provider, openai_compatible, openai | Provider |
| `ai_sdk_anthropic`, `ai_sdk_google`, `ai_sdk_cohere`, `ai_sdk_ollama` | provider | Providers |
| `ai_sdk_json_schema` | dart | Optional JSON Schema validation |
| `ai_sdk_mcp` | dart | MCP client |
| `ai_sdk_telemetry` | dart | OTLP/HTTP metrics export |
| `ai_sdk_conversation` | — | Conversation snapshots and codec |
| `ai_sdk_remote` | conversation | Trusted-backend UI-message-stream transport |
| `ai_sdk_flutter_ui` | dart, provider, conversation, remote | Controllers and widgets |
| `ai_sdk_realtime` | provider | Realtime sessions (unpublished) |

- Providers depend on `ai_sdk_provider` (the seam), optionally the `ai_sdk_openai_compatible`
  sub-seam, and an HTTP client. The core depends on the seam too, never on a concrete provider —
  that is what makes providers swappable.
- Companions never create a reverse dependency into the seam or core. `ai_sdk_conversation` is a
  persistence format, not a provider-prompt converter; `ai_sdk_remote` is a transport, not a
  persistence format (`docs/adr/0005-v3-public-contract.md`).
- `examples/remote_backend` is the reference trusted backend for `ai_sdk_remote`.

## Intentionally omitted

The web/framework-bound surface of Vercel AI SDK has no place in Dart/Flutter and is deliberately
absent: the React/Svelte/Vue/Solid UI hooks (`useChat` etc.), RSC (`streamUI`), and
Next.js/Node/Edge runtime glue. Flutter controllers replace the hooks
(`docs/adr/0002-v6-parity-scope.md`).

The UI-message stream protocol is no longer omitted: `ai_sdk_remote` consumes it from a trusted
backend (`docs/adr/0006-remote-conversation-transport.md`). The SDK does not produce that stream
on a Dart server, and does not retry or resume a disconnected stream.
