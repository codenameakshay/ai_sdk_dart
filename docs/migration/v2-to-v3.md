# Migrating AI SDK Dart 2.x to 3.x

This guide is being qualified alongside v3. The [contract ADR](../adr/0005-v3-public-contract.md) describes the full target; the [execution ledger](../../plans/v3-execution.md) identifies changes still in progress. Do not publish this working guide as a declaration that v3 has shipped.

## Custom provider cancellation

Use `AbortSignal` from `ai_sdk_provider` for every model family. It exposes `isCancelled` and `onCancelled`. The old `LanguageModelV4AbortSignal` name is a deprecated type alias retained throughout the v3 major line, so existing implementations remain assignable.

```diff
-class RequestSignal implements LanguageModelV4AbortSignal {
+class RequestSignal implements AbortSignal {
```

Forward the call option's signal to the actual HTTP request. Checking it only before a request does not provide active transport cancellation. SDK operations can settle without cooperation from a custom provider, but the provider still owns releasing its resources.

## Custom embedding models

Implement two additional capability getters:

```dart
int? get maxEmbeddingsPerCall => 128;
bool get supportsParallelCalls => true;
```

Use a verified provider limit. `null` means unspecified, not known-unlimited. Return false when concurrent requests cannot safely share your model. The [compiling custom-provider example](../../packages/ai_sdk_provider/example/custom_embedding_model.dart) illustrates the interface with deterministic example vectors; it is not a semantic embedding algorithm.

`embedMany` separates request size from concurrent requests:

```diff
 final result = await embedMany(
   model: model,
   values: documents,
+  maxEmbeddingsPerCall: 64,
   maxParallelCalls: 2,
 );
```

Concurrency defaults to one. The SDK chooses the smaller explicit/provider batch limit and preserves original input order even when requests finish out of order. Malformed responses now fail with `AiInvalidEmbeddingResponseError`: missing or extra rows, duplicate or out-of-range indices, empty/nonfinite vectors, and inconsistent dimensions are not silently accepted. Completely unindexed OpenAI-compatible responses retain list-order behavior; partially indexed responses fail.

## Structured output

A decoder alone does not establish JSON Schema validation. Keep decoder-controlled behavior explicitly:

```dart
final schema = Schema<MyValue>.decoderOnly(
  jsonSchema: myJsonSchema,
  fromJson: MyValue.fromJson,
);
```

Or install the optional `ai_sdk_json_schema` package and use `validatedJsonSchema<MyValue>` with the same schema/decoder inputs. It validates before calling the decoder. Local references are supported; external schema fetching is disabled. Draft 7 and 2020-12 are explicit supported dialects; format is treated as annotation.

`streamObject` partial snapshots are immutable JSON maps. They may lack required fields and must not be treated as complete instances of your application class. Await `object` for the validated final value. Incomplete JSON previews can be displayed, but incomplete final JSON must fail rather than become successful output by repair.

Cancellation and deadlines now settle final futures and active stream surfaces. A total deadline includes a silent upstream stream. Late errors cannot overwrite the original terminal outcome. Custom providers must still honor the signal to release network resources promptly.

## Response history

Append `responseMessages` once to the history you supplied. It now contains only messages generated by the current call. `prepareStep` message compaction changes model input without removing generated turns from this returned history.

```text
Before: request history + generated turns returned as response history
After:  request history stays with caller; response history = generated turns
```

## MCP replay

A lost reply to `tools/call` is ambiguous: the server may already have performed the action. The SDK no longer automatically retries that call. Handle `MCPAmbiguousToolCompletionException` by checking the remote outcome or asking the application's workflow to reconcile it. Set `retryOnTransportFailure` only for a call whose replay is safe.

Select modern protocol behavior explicitly using `MCPProtocolMode.modern`; legacy handshake behavior remains available. Modern discovery, per-request metadata and POST subscriptions are a different strategy, not just a new version string. Authorization callbacks provide host-owned token access; browser login, PKCE and credential storage remain application responsibilities.

## Instructions and callbacks

Use `instructions` for the top-level instruction. Existing `system` remains a
fallback; `instructions` takes precedence when both are supplied. System-role
messages are now rejected by default, before a provider request. Move trusted
instructions to the top-level option, or explicitly set
`allowSystemInMessages: true` for existing trusted histories.

`prepareStep` receives the current instructions. A non-null returned instruction
persists into later steps; an empty string clears it. Message compaction does
not discard returned response history.

Use `onEnd`, `onStepEnd`, `onStart`, `onStepStart`, `onToolExecutionStart` and
`onToolExecutionEnd`. Legacy callbacks remain fallbacks. If both forms are
provided, only the canonical callback runs. Start and step-start events expose
the effective instructions.

## Aggregate results and finalStep

`usage`, `content`, `toolCalls`, `toolResults`, `sources`, `files` and `warnings`
now aggregate every step. `text` and structured `output` retain final-step
semantics. Use `finalStep.usage` for last-step token accounting. The retained
`totalUsage` name refers to the same aggregate as `usage`. Streaming result
futures and the final event follow the same rule.

Each step exposes its own `responseMessages`, request/response metadata and
provider metadata. Append generated provider messages to user-facing history
using `result.responseMessages.map(ModelMessage.fromProvider)`; the conversion
keeps multimodal content parts intact.

The [runnable migration example](../../packages/ai_sdk_dart/example/migration/v3_generation.dart)
uses canonical callbacks and reuses returned messages in a second call. It runs
as part of the core test suite.

## Canonical streams and body inclusion

`stream` is the exhaustive core event stream. `providerStream` exposes the
provider-part stream for adapter integrations, and `fullStream` remains a
deprecated alias of `stream` during v3. It does not create a second producer.

```dart
final result = await streamText(
  model: model,
  prompt: 'Say hello.',
  bodyInclusion: const BodyInclusionPolicy.all(),
);
final events = result.stream;
final providerParts = result.providerStream;
assert(identical(events, result.fullStream));
```

Request and response bodies, plus raw chunks, remain omitted by default. Use a
typed `BodyInclusionPolicy` only when an integration has a reason to retain
those payloads and can protect their contents. The compiling contract example
is [`v3_contracts.dart`](../../packages/ai_sdk_dart/example/migration/v3_contracts.dart),
covered by `v3_contracts_example_test.dart`.

## Context and request approval

Use `toolWithContext` when a tool needs typed application context. The context
is delivered to the executor and is kept out of provider messages and
persistence. Put approval at the request or agent boundary:

```dart
final tool = toolWithContext<Map<String, dynamic>, String, String>(
  context: 'tenant-1',
  inputSchema: jsonSchema({'type': 'object'}),
  execute: (input, tenant, _) async => '$tenant:${input['value']}',
);

final result = await generateText(
  model: model,
  prompt: 'Use the tenant tool.',
  tools: {'lookup': tool},
  approvalPolicy: ToolApprovalPolicy.always,
);
```

An approval request is not an executed result. On restore, bind a response to
the exact call ID, arguments and policy revision before executing it. The
example and test exercise construction and execution without a provider key;
device and hosted approval UX remain separate qualification work.

## Files and provider references

Use canonical file parts for bytes, URLs and opaque provider references. Keep a
provider reference namespaced so another adapter cannot mistake an ID for a
URL:

```dart
const file = LanguageModelV4FilePart(
  data: DataContentProviderReference(namespace: 'openai', id: 'file-1'),
  mediaType: 'application/pdf',
  filename: 'contract.pdf',
);
final message = ModelMessage.parts(
  role: ModelMessageRole.user,
  parts: [file],
);
```

The receiving provider decides whether it can serialize that namespace. It
must reject an unrelated provider reference rather than downloading or
reinterpreting it as a URL. Byte and URL examples are covered by provider and
conversation fixtures; live hosted-file qualification is still outstanding.

## Persisted conversations and remote transport

Conversation persistence is independent of package version. Encode and decode
the immutable snapshot with `ConversationCodec`, then send the restored state
through the remote transport when the application has an authenticated
backend:

```dart
final wire = ConversationCodec.encode(conversation);
final restored = ConversationCodec.decode(wire);
final transport = RemoteConversationTransport(
  endpoint: Uri.parse('https://example.test/api/chat'),
);
await for (final update in transport.send(restored)) {
  // Render immutable snapshots; the remote adapter does not execute tools.
}
await transport.dispose();
```

The runnable persistence example is
[`packages/ai_sdk_conversation/example/example.dart`](../../packages/ai_sdk_conversation/example/example.dart).
The remote example and pinned backend are
[`packages/ai_sdk_remote/example/example.dart`](../../packages/ai_sdk_remote/example/example.dart)
and [`examples/remote_backend`](../../examples/remote_backend). They prove
offline codec and scripted transport behavior. They do not certify browser
resumption, production authorization, provider-key isolation, or device
qualification.

## Aggregate results and final-step reasoning

`usage`, `content`, `toolCalls`, `toolResults`, `sources`, `files`, warnings,
and reasoning aggregate successful steps in chronological order. `text`,
structured `output`, and `finalStep` describe the last successful step. Read
`finalStep.reasoning` when the application needs reasoning from only the final
step; read `result.reasoning` when it needs the aggregate. A failed or
interrupted operation does not invent a final step.

The migration example in
[`v3_contracts.dart`](../../packages/ai_sdk_dart/example/migration/v3_contracts.dart)
and its focused test compile these public boundaries. Overall v3 release
qualification remains incomplete until live provider, platform, hosted-file,
and production remote evidence is collected; these examples document the
contract and do not replace that evidence.

## Realtime preview packaging

`ai_sdk_realtime` is versioned as `3.0.0-dev.1` and remains
`publish_to: none`. It is intentionally excluded from the stable package
publication set until authenticated transport, bounded lifetime, mobile and
desktop device behavior, and typed event qualification are complete. The
preview package can track the v3 contracts in the workspace without making a
stable realtime support claim.
